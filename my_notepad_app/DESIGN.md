# 个人记事本 APP 产品设计文档 (PRD & 架构构思)

## 1. 产品定位与目标
- **目标用户**：需要多端同步、注重记录效率和灵感捕获的个人用户。
- **核心理念**：**“快”与“多端合一”**。记录要快，不需要繁琐的步骤；查看要方便，无论是手机、网页还是电脑都能随时访问。
- **平台规划**：
  - **移动端（首发主打）**：iOS 和 Android 客户端，侧重于快速记录和移动场景下的阅读。
  - **Web 端**：通过浏览器访问，侧重于长内容的编辑、整理和全局检索。
  - **Windows/PC 端**：独立的桌面应用程序（exe），侧重于沉浸式办公和全局快捷键呼出。

## 2. 核心功能设计 (参考知名应用)

### 2.1 笔记记录与编辑 (参考 Apple Notes, Notion)
- **富文本编辑**：支持加粗、斜体、列表、待办事项 (Checklist)、引用等基础排版。
- **混合内容支持**：支持插入图片、录音、简单的手绘涂鸦。
- **Block 层级 (可选进阶)**：像 Notion 一样将内容块化，方便后续拖拽重组。

### 2.2 组织与分类 (参考 Evernote, 印象笔记)
- **多层文件夹/笔记本**：用于归档重度内容。
- **标签系统 (Tags)**：像 Flomo 一样，通过 `#标签` 快速分类，适合碎片化内容的交叉索引。
- **全局搜索**：支持对标题、正文乃至图片内的文字（OCR）进行快速搜索。

### 2.3 数据同步 (参考 Google Keep, 备忘录)
- **云端实时同步**：多设备登录同一账号，数据毫秒级同步。
- **离线可用**：在没有网络的情况下也能新建和查看笔记，网络恢复后自动合并同步（支持解决冲突）。

## 3. 核心亮点功能：独立呼出的“速记功能” (Quick Capture)

这是该应用的最大亮点，旨在让用户在产生灵感的一瞬间，用最短的路径完成记录，而不必“打开APP -> 寻找新建按钮 -> 甚至还要选文件夹 -> 输入”。

### 3.1 移动端 (手机) 速记实现
- **通知栏/控制中心快捷键**：在 Android 的下拉控制中心或 iOS 的小组件中放置“一键速记”按钮。
- **悬浮窗/全局快捷呼出 (Android)**：授权悬浮窗权限后，可以在屏幕边缘常驻一个半透明的“笔”图标，点击直接弹出输入框（类似锤子手机的“闪念胶囊”或三星的 S Pen 快捷笔记）。
- **锁屏小组件 (iOS 16+)**：锁屏界面一键启动速记界面。
- **分享扩展 (Share Extension)**：在浏览器或其他APP中，选中文字或链接，点击分享，直接通过本APP的速记面板保存，不打断当前阅读。
- **语音速记**：支持长按速记按钮直接说话，自动语音转文字（STT）并保存为文本+录音。

### 3.2 桌面端 (Windows exe) 速记实现
- **全局快捷键**：例如设置 `Ctrl + Alt + N` 或 `Alt + Space`。在电脑运行任何软件时，按下快捷键，屏幕中央立刻弹出一个极简的输入框（类似 macOS 的 Raycast、Spotlight 或是全局呼出的 Flomo 输入框）。
- **随打随关**：输入完内容，按下 `Enter` 直接保存并后台上传，按下 `Esc` 关闭面板，丝毫不影响原有工作流。
- **剪贴板监听（可选）**：复制多段内容后，快捷键呼出时可自动粘贴并保存。

### 3.3 网页端 / 浏览器插件
- **浏览器扩展程序**：点击扩展图标弹出小窗，或者右键菜单“保存到我的记事本”。

## 4. 技术栈选型建议

为了实现上述功能，并保持高效的开发进度（一人或小团队），建议采用以下技术栈：

### 4.1 前端 (大前端跨平台方案)
- **移动端 (iOS & Android)**：
  - **Flutter** 或 **React Native**。两者均能实现一套代码多端运行，且能通过原生插件实现悬浮窗、小组件等特殊“速记”入口需求。
- **Web 端**：
  - **React** 或 **Vue 3**。配合 TailwindCSS 构建现代化的响应式界面。
- **桌面端 (Windows exe)**：
  - **Tauri** 或 **Electron**。
  - 推荐使用 **Tauri** (基于 Rust)，打包出来的 exe 体积极小（不到 10MB），内存占用低，非常适合做常驻后台监听“全局快捷键”的记事本应用。前端部分可以直接复用 Web 端的代码。

### 4.2 后端与数据库
- **后端框架**：Node.js (NestJS/Express) 或 Go 或 Python (FastAPI)。
- **数据库**：PostgreSQL (结构化数据) + Redis (缓存)。
- **BaaS 替代方案**：如果不想自己维护服务器和登录、鉴权逻辑，可以直接使用 **Supabase** 或 **Firebase**。它们提供了开箱即用的实时数据库、离线同步SDK和用户认证系统，极大地降低了开发成本。

### 4.3 离线同步与富文本编辑器选型
- **离线与同步方案**：可以使用 CRDT（无冲突复制数据类型）相关的库（如 Yjs 或 Automerge）来实现高级的多端同步和离线编辑。
- **富文本编辑器**：推荐集成如 `ProseMirror`、`Quill` 或 `TipTap`，它们支持移动端和Web，且扩展性极强。

## 5. 第一阶段 (MVP) 开发路线

1. **原型设计**：画出移动端主界面、速记弹窗界面的线框图。
2. **移动端 MVP**：使用 React Native / Flutter 开发。实现：登录、列表展示、新建/编辑笔记。
3. **速记功能攻坚**：编写原生插件，实现 Android 的通知栏快捷操作/悬浮窗，或 iOS 的 Share Extension 分享组件。
4. **后端跑通**：接入 Supabase，实现手机端数据的增删改查及云同步。
5. **桌面/Web 衍生**：使用相同的前端组件库搭建 Web 版，并用 Tauri 包装为 Windows exe，实现 `全局快捷键唤出`。
