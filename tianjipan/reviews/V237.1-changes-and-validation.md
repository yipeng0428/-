# 天机盘 V237.1 修订说明与验证

已基于用户上传的 V237 生成 `releases/天机盘_v237_安全稳定修订版.html`，仍保留独立 HTML 的交付方式。这一版集中修复能复现的安全、存储、输入隔离、模块契约和重复加载问题。没有重新设计全部页面，也没有把历史资料自洽检查提升为独立天文精度证明。

原始 V237 仅比 V236 新增四余历元验证样式及两个脚本，原有 184 个脚本均未修复。V236 的完整架构审查仍适用于 V237，详见 `V236-technical-review.md`。ChatGPT 分享链接在本环境返回连接拒绝，未读取其他聊天记录；本次依据两份上传文件和实际运行结果。

## V237 专有问题：罗计对冲自测容差

原始 V237 的 `epoch.node.opposition` 自测实际失败：传统度误差为 `0.000001515`，代码却要求小于 `0.000001`。这不是修改历元常数的理由。

至后策只保留四位小数，两个相位相减的舍入误差上界为 `0.0001` 日；按 `18.59910776` 日/传统度换算，容差为约 `0.000005377` 传统度。修订版依据这个输入精度定义容差，并在检查详情中同时输出误差和容差。原始相位常数、1281→1384 闭合数值、1384→1578 长期漂移数值全部保持一致。

V228 另有一处过期自测：实际数据已是逆推格里高利历 1578-01-18，却仍期待 1578-01-08。修正期望值；儒略历日期仍为 1578-01-08。没有改变历史锚点绝对日。

保留原 V237 的 provider 策略与审查用途，不自动用大统历元漂移重校准正式结果。量天尺自动图格输出也不静默覆盖人工校准。旧版全局童限不自动分配给任何人物；这可以避免把一个人的设置复制到所有盘。

## 验证结果

可运行脚本为 `tests/v237-regression.cjs`，记录为 `V237.1-validation.json`。

- 186 个 inline script 块通过语法解析；静态 HTML 未发现重复 ID。修订版相对原 V237 的 diff --check 通过；全量新增文件检查报告原始 HTML 已有的行尾空白，原始文件及未改动代码保持原样。
- 25 组针对实际故障路径的检查通过，包括恶意 JSON 文件导入、刷新后无脚本执行、旧存储迁移、合盘文字注入、配额失败回滚、旧镜像失败、校准隔离和恢复、固定盘计算不依赖表单、闰年与无效日期、0 坐标、紫微适配器、版本稳定、缓存篡改和并发加载。
- 内置完整 QA：55 项，49 PASS、5 WARN、0 FAIL；另有 1 项 INFO，不计入前三项。门禁是“条件通过”，不是无条件发布。
- 在 Chromium 的 390×844 视口切换此刻、人物、关系图、八字、奇门、紫微、七政七个主要面板，文档宽度没有超出视口；在七政页面补做手机布局门禁，0 FAIL。
- 使用从固定 npm 包中提取且已验证 package SHA-512 的两份源码作为网络夹具，iztro 和 lunar 均成功加载；iztro 启动并发只发起一次请求。另测试篡改缓存，不会执行。
- 在同样阻断所有外网的首屏条件下，原 V237 发起 53 次外部请求，修订版发起 7 次，减少约 87%。这是请求次数优化，不代表加载耗时提升 87%。
- 单次加载耗时有波动，不能据此承诺整体速度提升。HTML 仍约 5.99 MB，脚本解析、历史包装层与 DOM 渲染仍是主要开销。
- 比较原 V237 与修订版的历元链和漂移统计完全一致；同时比较了一个排盘样例的昼夜、命宫和命度。没有逐条验证所有术数规则。

5 项 WARN 分别是：奇门日/月/年的独立外部 reference 不足、旧 QA 中七政研究/许可缺口提示、六爻深度没有 selfTest、house/hetu/review 三个 factory 采用直接渲染而非返回字符串，以及桌面 QA 提醒补做手机验收。七政提示来自旧版门禁，不能据此推断新增星历链全部不可用；也不能用新增内部测试推断所有流派规则已得到外部验证。

本次浏览器测试通过本地 HTTP；执行环境禁止 `file://`，未验证直接双击。第三方网络行为主要使用失败拦截及可信夹具，不能保证所有用户地区的 CDN 可用。缺少 Web Crypto 的 HTTP 来源会拒绝运行无法验证的外部代码，核心页面保持独立。

## 使用与迁移

1. 在原版导出人物 JSON 并妥善备份，再打开新文件、导入主库。换文件名、浏览器、网址可能改变 localStorage 的来源，不能保证直接看到旧数据。
2. 旧全局童限不继承；载入需要校准的出生输入，重新设置人工校准。改变出生时间、坐标或选项后是新的校准输入。
3. 人物导出文件包含私人资料，应由用户自行保管。本仓库只保存原始应用、修订应用与测试中的虚构人物证据，不保存真实浏览器人物库或密钥。
4. 文件保留单 HTML 用法。开发复核建议本地 HTTP，详见项目 README。

## 下一阶段建议

优先把“开发源码”和“交付单文件”分开：源码拆成计算、人物存储、外部 provider、界面与证据模块，构建时仍可输出一个 HTML。逐步删除相互包装的历史启动脚本，比继续附加补丁更有利于长期维护。

计算层建立明确的输入/输出契约，把时区、地点、日界、流派和规则版本纳入计算上下文与缓存键。优先整理八字/奇门/紫微的时间边界样例，以及七政宿度边界和多人物批量样例；缓存的 selfTest 结果只证明初始化时的检查，不能代替当前环境重新验证。

大量人物与长报告建议使用 IndexedDB 事务和数据版本迁移；明确多标签冲突处理、导入预览与备份恢复。关系两两分析是 O(n²)，应只计算可见关系或限制批量规模。2000 人导入上限只限制输入，不代表2000人全关系图性能已经验证。

性能下一步先分段渲染长报告、按需初始化真正用到的验证器、合并 DOM 更新和观察器，测量首屏长任务和输入延迟。把确定性批量计算放进 Web Worker 前，先明确序列化边界；不要把 Worker 当作自动加速手段。

安全方面，本次 SHA-256 保护的是 lunar 和 iztro 两个直接执行的校验器入口；其他远端模块、AI 接口和全部 DOM 写入没有完成同等程度的全覆盖验证。正式上线后，API 密钥建议由服务端代理保管，部署 CSP 并限制连接目标；单文件原型不宜承担真实账号鉴权或多用户共享数据。
