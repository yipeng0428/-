# 天机盘 V237.2：代码整理、性能与稳定性验证

交付：[独立 HTML](../releases/天机盘_v237.2_代码整理性能优化版.html)。以 V237.1 为基底，保留 V237 三历元证据链及生产 Provider 的选择，整理源码、删除可证实的冗余启动工作，并加强外部库加载。原始文件与 V237.1 文件均保留。构建不再依靠追加历史补丁。

## 实测变化

| 项目 | V237.1 | V237.2 |
| --- | ---: | ---: |
| HTML 字节 | 5,990,230 | 5,580,371 |
| 默认启动外部请求 | 7 | 0 |
| DOMContentLoaded 中位时间 | 3351.4 ms | 2978.4 ms |
| 启动后的 DOM 变动记录数（中位） | 64 | 33 |
| 点击七政页后的 DOM 变动记录数（中位） | 51 | 42 |

文件减少 **6.8%**；本次解析就绪中位时间缩短 **11.1%**。同一 Chromium 中交替加载新旧文件，各三个全新 context，阻断外网，启动等待 1000 ms，点击七政后等待 500 ms。DOM 计数只统计所述观察窗口；DOMContentLoaded 不等于整个页面异步工作全部结束。这些数据反映当前容器，不是所有设备的提速保证。七政顶层公开计算入口仍为一次调用，没有宣称排盘数学运算倍速提升。原始逐次数据保存在 [验证证据](V237.2-validation.json)。

## 删除与合并的内容

- 删除 17 个后续版本 authority 脚本和一个失效的版本锁标记，停止历史模块反复改写页脚。可见版本由 `release.js` 发布，保留必要的能力标记。
- 将 17 层 `refRender` 包装合并为一个页面扩展调度器。按原注册顺序挂载奇门和七政扩展，用一次 RAF 合并同轮请求。调度以页面渲染完成为依据，移除 14 个使用错误导航属性的无效分支，避免在导航点击和实际渲染两个时点重复挂载。
- 移除天机式每 1400 ms 扫描 DOM 的轮询，改为天象页面渲染后挂载；验证实际点击后按钮和工作区都存在。
- 移除三个外部校验器的自动启动入口及 15 个紫微版本的自动对拍调用。主排盘无需这些外部请求，用户仍可在校验页运行对拍。
- 停止写入人物库的旧版 v3 镜像，减少重复序列化和同步存储写入。主库提交失败仍回滚内存；旧人物 v3 数据的迁移读取、关系、本人和位置映射都保留。
- 历法和紫微校验器不再读写 localStorage 可执行源码，仅合并进行中的内存加载请求。只移除两个确切的退休缓存键；不调用 `localStorage.clear()`，不删除个人资料、设置和校准记录。
- 删除 111 个历史系统元数据 `previous` 链接、52 处顶层启动日志、135 个空的历史分支及三处无意义的调用。实际算法 `base` 依赖和上一节气数据保留。
- 构建时去掉同一 CSS 容器内的 66 条完全重复规则，保持样式和功能脚本的原始顺序。未用“当前 DOM 没有这个类”作为删除动态样式的依据。

源迁移位置记录：[V237.2-source-cleanup.json](V237.2-source-cleanup.json)。部分页脚改写位置是重叠候选，因此没有把候选总数当成独立修复数。

## 外部库的稳定性与安全边界

Astronomy Engine 移除了两条无需内容校验的直接脚本回退路径。固定 CDN 和 GitHub 来源仍由 V227 完整性加载器处理，校验失败则保留 Legacy Provider，不通过另一路径执行相同未验证源码。添加每个来源的 8 秒可中止请求上限，修复“并发只缓存任务完成，却把 Engine 报成已加载”的竞争条件。

有效的 Astronomy 离线缓存保留，读取后仍验证固定字节数及 Git blob 摘要；它有明确离线用途，不属于废弃缓存。两个退休校验器缓存不执行也不再回写。

Mystilight 的旧加载器直接 `import` CDN 模块，超时后下载与执行可能仍继续。新版先中止超时请求，核对固定 2,214,349 字节和 SHA-256，再从内存 Blob 导入已验证的自包含模块；`finally` 撤销 Blob URL，不新增持久脚本缓存，并合并并发重新加载。SHA-256 来源是已核对原有 Git blob 的固定 GitHub 提交，未改变原有校验值去迎合下载内容。该大型模块按需加载，不嵌入交付 HTML。

四个开发夹具都经正常 TLS 下载和固定 SHA-256 检查。验证包括：同长度恶意八字模块拒绝执行、被修改星历拒绝执行且不插入外部脚本、可信源可加载、并发请求共用一次下载、缓存和加载同时进行后确实建立 API。证据：[Mystilight 加载验证](V237.2-vendor-loader.json)。

## 可维护源码与可复现构建

`src/js/core/` 将主脚本拆成十个职责文件，静态典籍、姓名、原图片内容存入 `src/assets/`。`src/blocks.json` 明确执行与样式顺序，构建时重新合成单 HTML。保留经典脚本的全局词法作用域，避免为改排版改变算法、流派或时间输入关系。

`tools/build.mjs` 读取当前源码，不加载历史 HTML、不重放迁移补丁。JavaScript 使用保守压缩，不混淆名称、不启用 unsafe 优化；保留许可注释。依赖版本和完整性由 lockfile 固定，node_modules、下载夹具、日志和缓存不进入 Git。旧的 V237.1 重建脚本只作为历史重建入口。

## 验证结果

- 25 组原有稳定性回归全部通过：日期有效性、零经度、输入纯度、不同命主校准隔离、飞星、人物/关系导入防注入、旧数据迁移、存储空间不足时回滚、移动宽度、延迟版本写入等。
- 24 组日期 × 性别 × 经度的时间、八字、农历、奇门、紫微及选定七政结果，与 V237.1 一致，含闰日、晚子时及零经度；V237 历元链、长期漂移数字及 V228 回归也一致。
- 44 个实际导航入口逐一点击，页面存在且无未捕获错误。七政 14 个扩展 section 的 ID 集合与旧版一致；闲置页面不再持续重挂载。
- 历法、紫微、Mystilight、Astronomy 可信夹具加载及篡改拒绝测试通过。
- 原始典籍、姓名数据和捐赠图片嵌入内容逐字一致；核心静态资料没有改写。
- 内置完整 QA：55 项，49 PASS、5 WARN、1 INFO、0 FAIL；手机布局 QA：35 项，32 PASS、2 WARN、1 INFO、0 FAIL。警告包括历史路线图状态、缺少独立 selfTest 接口、返回值口径和测试视口提示；没有把既有 WARN 改成 PASS。44 个入口另有实际点击验证。
- `npm ci`、云环境安装脚本、四夹具固定下载、格式检查及确定性重建通过。重复构建的 SHA-256 与已测试文件一致。

## 保留的限制与后续方向

仍存在实际使用的历史算法层和全局状态；这些层之间有运行依赖，不能把版本号旧或名字带 patch 的模块一概删除。当前整理没有完成整个应用的状态隔离，也不能保证所有潜在漏洞均已排除。

极早日期及真太阳时跨日期时仍需结合底层农历数据范围验证；本次 24 组一致性测试不等于覆盖全部日期。术数解释、宿界和历史星历的科学准确度不由浏览器回归证明。

后续最有价值的工作是把人物输入、时间上下文、计算和渲染逐步隔离，并为计算建立明确输入契约；然后针对择日、批量时间轴与星历推演的真实热点考虑 Worker。严格 CSP 需要进一步减少内联和动态执行路径，应与部署方式一起设计。

直接双击 `file://` 在本次云环境被策略禁止；当前验证经 HTTP 回环服务完成，未完成该模式及真实手机、Safari/Firefox 的验证。浏览器数据按来源保存，换文件或域名可通过人物 JSON 转移。
