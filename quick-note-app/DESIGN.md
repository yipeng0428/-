# QuickNote 记事本 App 设计方案

## 1. 核心需求分析

*   **多端支持**：以手机端（Mobile）为主，要求支持网页端（Web）同步，并考虑未来 Windows 桌面端（Win exe）的支持。
*   **速记功能**：这是最核心的亮点，需要一个可以独立呼出的快速记录入口，要求“轻量、迅速、无感”。
*   **基础记事本功能**：参考当前主流记事本，如 Apple Notes、Notion、Evernote、Flomo、Google Keep 等。

## 2. 功能模块设计

### 2.1 独立速记功能 (Quick Capture)

这是本 APP 的灵魂功能，参考对象：Flomo 的灵感记录、Mac 上的 Raycast/Alfred、iOS 的控制中心备忘录。

*   **手机端唤醒方式**：
    *   **Android**：支持桌面小组件（Widget）、通知栏常驻快捷按钮、甚至锁屏快捷键。可以实现点击即弹出一个悬浮的半屏输入框，不需要完全打开 APP 的主界面。
    *   **iOS**：利用 Share Extension（分享菜单直接记）、锁屏小组件（Lock Screen Widget）或控制中心快速打开，或者长按 APP 图标直接新建。
*   **速记体验**：
    *   打开极速（秒开）。
    *   界面极简：只有一个文本框，自动弹出键盘，可以插入图片/语音。
    *   保存极快：写完点击“发送/保存”（或下滑关闭），即刻在后台同步，不打断当前工作流。

### 2.2 基础记事与管理 (Main APP)

参考 Apple Notes、Google Keep 等。

*   **层级与组织**：
    *   标签系统（Tags）：比文件夹更灵活，适合速记碎片的组织（参考 Flomo/Obsidian）。
    *   文件夹（Folders）：满足传统分类需求。
*   **编辑器**：
    *   富文本编辑（加粗、列表、待办事项）。
    *   支持 Markdown 快捷输入（如输入 `# ` 变标题）。
    *   图片和附件上传。
*   **搜索与回顾**：
    *   全局全文搜索。
    *   按标签、日期筛选。

### 2.3 数据同步 (Sync)

*   云端实时同步。支持多设备同时在线。
*   离线可用：在无网络下可以查看和新建，网络恢复后自动合并（需要处理冲突，类似 CRDT 或简单的最后修改时间覆盖）。

## 3. 技术栈建议 (如何实现多端)

为了实现“手机端为主，网页端同步，Win端可安装”，最经济高效的选择是跨平台技术栈。

### 方案 A：React Native / Expo (推荐)

*   **手机端 (iOS & Android)**：使用 React Native (Expo) 构建，体验接近原生，生态丰富，支持各种小组件和原生模块扩展（可以实现速记的独立唤醒）。
*   **网页端 (Web)**：React Native for Web 可以复用大量组件，或者直接用 React 单独写一个 Web 前端复用状态管理。
*   **桌面端 (Windows)**：网页端可以直接打包成 PWA 安装在桌面，或者使用 Electron / Tauri 套壳打包成 exe，甚至可以使用 React Native for Windows。

### 方案 B：Flutter

*   **优势**：一套代码可以编译到 iOS、Android、Web、Windows。性能好，UI 高度一致。
*   **劣势**：网页端加载体积稍大，对于“速记”功能需要写一些原生代码（如 Android 的悬浮窗或桌面小组件）。

### 方案 C：Tauri + Web 框架 (Vue/React/Svelte)

*   主要针对 Web 和 Desktop 体验极佳。
*   手机端近期 Tauri 也在支持（Tauri Mobile），但成熟度不如 RN/Flutter。如果考虑后续包装成 PWA 在手机上用，也是一种超轻量方案，但不易实现系统级的“独立呼出”体验。

### 数据与后端架构推荐

*   **BaaS (后端即服务)**：为了快速开发，推荐使用 **Supabase** 或 **Firebase**。它们提供了开箱即用的：
    *   身份认证（登录注册）
    *   实时数据库（PostgreSQL/NoSQL），支持离线同步机制
    *   对象存储（存图片）
*   **本地存储**：SQLite 或 MMKV，保证极速启动和离线可用。

## 4. 第一阶段实施步骤建议 (MVP)

既然您最想先做手机端并验证速记功能，建议遵循 MVP (Minimum Viable Product) 原则：

1.  **确定技术栈**：推荐使用 Expo (React Native) + Supabase。
2.  **实现核心 UI**：
    *   一个主列表页（展示所有笔记）。
    *   一个详情/编辑页。
    *   **一个独立的速记组件**（设计为一个从底部弹出的 Modal 或独立的半透明 Activity）。
3.  **实现速记唤醒**：在 Android 上探索快捷方式/通知栏唤醒速记 Modal，在 iOS 上实现 Share Extension。
4.  **跑通同步**：接入 Supabase，实现笔记的增删改查和云端同步。
5.  **Web 适配**：将 Expo 项目编译为 Web 版本，或复用逻辑部署一个 React Web 站点。

如果您同意这个方向，我们可以开始初始化项目结构（例如使用 Expo 创建一个基础应用），或者我们可以先深入讨论某个特定模块（比如如何设计那个速记界面）。
