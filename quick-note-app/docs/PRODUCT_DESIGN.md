# 记事本APP (Quick Note App) 产品设计文档

## 1. 产品定位与愿景

本应用致力于提供一款跨平台（首发移动端，后续扩展Web/Windows客户端）、轻量级且高效的记事本工具。其核心优势在于极速的记录体验与便捷的多端同步。无论是灵感闪现还是日常备忘，都能随时随地，即刻记录。

## 2. 竞品参考与分析

*   **苹果备忘录 (Apple Notes):**
    *   **优点:** 深度集成系统，启动快，同步稳定，原生体验好。
    *   **启发:** 借鉴其简洁清爽的UI，以及通过控制中心快速创建备忘录的能力。
*   **Notion:**
    *   **优点:** 强大的Block体系，适合复杂的文档管理和知识库。
    *   **启发:** 适合作为后续扩展的高级格式支持参考，但在初期我们更侧重于轻量化记录。
*   **Evernote (印象笔记):**
    *   **优点:** 跨平台支持全面，信息收集能力强。
    *   **启发:** 强大的同步机制，但其客户端显得有些臃肿，我们需保持轻快。
*   **Flomo (浮墨笔记):**
    *   **优点:** 极简的卡片式笔记，主打随时随地的碎片化记录，无压力。
    *   **启发:** **重点参考**其无压力的输入框设计和通过快捷指令/小组件快速记录的理念，非常符合我们的“速记”需求。

## 3. 核心功能规划 (MVP版本)

### 3.1 独立速记功能 (Quick Note) - **核心卖点**
*   **目标:** 以最快、最无感的方式捕捉稍纵即逝的灵感。
*   **实现方式 (移动端):**
    *   **桌面小组件 (Widget):** 提供不同尺寸的桌面小组件，点击小组件即可直接呼出输入框，无需进入App主界面。
    *   **系统快捷入口:**
        *   iOS: 结合 Shortcuts (快捷指令) 提供控制中心或锁屏界面一键启动。
        *   Android: 利用 Quick Settings Tile (下拉控制中心开关) 提供快速入口。
    *   **分享面板集成:** 选中文本、图片或链接时，可通过系统的“分享”功能直接发送至“速记”，后台自动保存。
    *   **极简输入界面:** 呼出速记时，界面仅展示键盘和输入框（类似发送微信朋友圈或微博发布），输入完毕点击发送，自动保存并关闭，不打断用户当前操作。

### 3.2 基础记事管理
*   **创建与编辑:** 支持纯文本输入，后续可迭代支持富文本（加粗、列表、待办等）、图片插入。
*   **列表视图:** 按时间倒序展示笔记列表，支持瀑布流或列表模式。
*   **分类与标签:** 使用简单的文件夹或标签(#tag)系统对笔记进行分类管理。
*   **全文搜索:** 快速检索笔记内容。

### 3.3 数据同步
*   **方案:** 采用基于云的实时/异步同步方案（如 Firebase Firestore, Supabase，或自建简单的RESTful/GraphQL API + WebSocket）。
*   **策略:** 离线优先（Offline-first），在本地（如 SQLite/Realm/WatermelonDB）保存数据，网络恢复后静默同步至云端，保证弱网环境下的可用性。

## 4. 技术架构选型建议

考虑到希望“首发手机端，同时兼容Web，甚至打包为Win端exe”的需求，推荐以下跨平台方案：

### 4.1 方案 A: React Native (推荐)
*   **理由:**
    *   拥有庞大的生态，极具优势的跨平台能力。
    *   借助 React Native for Web，可以较高复用率地构建网页端。
    *   借助 React Native for Windows/macOS，可以将应用打包为桌面端原生应用。
    *   拥有丰富的第三方库支持小组件开发（如 `react-native-widget-extension`）和原生模块调用（针对速记入口）。
*   **技术栈:**
    *   框架: React Native (Expo 或 Bare CLI)
    *   状态管理: Zustand / Redux Toolkit
    *   本地存储: MMKV (极速存储) + WatermelonDB/SQLite (复杂查询)
    *   UI组件库: Tamagui 或 NativeBase

### 4.2 方案 B: Flutter
*   **理由:**
    *   性能优异，UI一致性极高（一套代码，多端渲染）。
    *   官方原生支持 iOS, Android, Web, Windows, macOS, Linux 甚至嵌入式设备。
*   **技术栈:**
    *   框架: Flutter
    *   状态管理: Provider / Riverpod / Bloc
    *   本地数据库: Isar / sqflite

### 4.3 方案比较与结论
对于前端开发者而言，如果熟悉 React，**React Native** 的上手成本最低，且能够很好地利用现有 Web 知识。如果追求极致的渲染性能和多端UI绝对一致性，且愿意学习 Dart 语言，**Flutter** 是更好的选择。

考虑到“速记”功能需要深度集成各系统的原生特性（小组件、控制中心、快捷指令），无论选择哪种框架，都需要一定的原生平台开发经验（Swift/Kotlin/Java）来编写桥接代码。

## 5. 后续迭代路线图

*   **Phase 1 (当前):** 移动端 MVP，完成基础记事、本地存储、核心的“独立速记”功能（桌面小组件/快捷入口）。
*   **Phase 2:** 引入云端同步机制，打通跨设备数据流；完善分类、标签、搜索功能。
*   **Phase 3:** 推出 Web 端及桌面端（Windows EXE）。
*   **Phase 4:** 丰富笔记内容格式（Markdown 支持、富文本、图片、录音），引入提醒功能。

## 6. 总结
本设计的核心在于“快”，通过多渠道、跨平台的入口设计，使得“速记”成为最轻量的认知外脑。优先移动端，离线优先的数据策略将保证最佳的用户体验。
